# 东江潮汐表 · 微信小程序

首页展示东江（广东惠州、东莞感潮段）**前 3 天 + 今天 + 后 7 天**的潮汐表，包含逐日潮汐曲线、高低潮时刻与潮高。

## 功能

- 日期条覆盖过去 3 天与未来 7 天，共 11 天，可左右切换。
- 潮汐曲线图（Canvas 2D 绘制），标注高潮 / 低潮点与当前时刻。
- 当日潮位时刻表（高潮 / 低潮时间与潮高）。
- 惠州、东莞两个站点切换（东莞更靠海，潮差更大、潮时略提前）。
- 顶部实时显示“当前潮位 + 涨/退潮状态”，每分钟刷新。
- 「气象增减水」Tab：展示博罗(二)站当前水位、实时台风与风暴增水，修正天文潮之外的部分。

## 数据来源说明

本程序采用 **天文潮汐调和常数模型**，在本地计算任意日期的潮位曲线：

- 主要分潮：M2、S2、N2、K2、K1、O1、P1、Q1、M4、MS4。
- 每站锚定一次 M2 高潮参考时刻，其余分潮用相对相位差（反映珠江口不规则半日潮特征），由此自然产生每天高潮推迟约 50 分钟的规律。
- 调和常数（振幅 / 相位）参考珠江口半日潮型近似取值，并已用**惠州港真实潮汐**（来源：国家海洋信息中心，经潮汐表网站公开转载）校准潮时与潮高量级，属**天文潮汐预测**。

> ⚠️ 本预测**未计入气象增减水与上游径流影响**（东江受降雨、泄洪、风浪影响显著），结果仅供参考，实际潮位以水文 / 海洋部门发布为准。

### 与真实潮汐表的对比（惠州港 2026-07-25）

已用真实潮汐数据（来源：国家海洋信息中心，经潮汐表网站转载）对 K1/O1 分潮相位与 M2 锚定时刻做一次拟合修正：

| 极值 | 真实数据 | 修正前 | 修正后 |
|---|---|---|---|
| 第一次高潮 | 04:49 | 03:56（偏早53分）| 04:43（偏6分）|
| 第一次低潮 | 11:46 | 11:01（偏早45分）| 11:45（偏1分）|
| 第二次高潮 | 17:51 | 17:23（偏早28分）| 17:57（偏6分）|
| 第二次低潮 | 22:40 | 21:29（偏早71分）| 22:22（偏18分）|

修正后潮时偏差从约 1 小时缩小到 **6–18 分钟**，逐日推迟规律（每天高潮晚约 35–40 分钟）保持正确。潮高量级吻合（高潮约 188cm vs 真实 176cm）。

> 残余偏差来自：① 各潮汐表网站数据本身不一致（同一日高潮给出 04:49/05:09/06:13 等不同值）；② 仅用 4 个极值点拟合，欠定。要进一步消除需权威调和常数（国家海洋信息中心，不公开）。

核心算法见 `utils/tide.js`。

## 气象增减水 Tab

第二个 Tab 展示天文潮汐无法覆盖的两部分（代码 `pages/surge/` + `utils/surge-data.js`）：

1. **博罗(二)站当前水位**：东江下游干流控制站，反映上游径流对下游潮位的顶托影响。并附说明：博罗是径流/淡水水位，非潮位；暴雨/泄洪时水位上涨会抬高下游高潮。
2. **实时台风与风暴增水**：有台风时显示其名称、位置、风力、等级，及风暴增水预报（如「广东揭阳到惠州沿海 80–160 cm 增水」）。

### 数据源现状（重要）

经调研，这两项**均无官方免费 JSON API**，且微信小程序前端 `wx.request` 无法解析动态渲染的 HTML：

| 项 | 调研结果 |
|---|---|
| 博罗站水位 | shuiwei.cc 为 SPA，水位由 JS 渲染，HTML 源码不含数值；水利部 xxfb.mwr.cn 为图片/表格 |
| 台风/风暴增水 | 国家海洋环境预报中心 nmefc.cn 动态加载难抓；中国天气网 d1.weather.com.cn 接口需 Referer 且实测被拒 |

因此 `surge-data.js` 采用 **「尝试请求公开源 + 失败降级为最近一次真实抓取示例」** 策略，UI 用标签标注数据状态：`实时` / `示例` / `获取失败`。当前默认降级显示 2026-07-25 调研抓取到的真实数据（博罗水位 1.03m、台风红霞 80–160cm 增水）。

要稳定获取真实数据，可选：

- **云函数抓取（已实现）**：`cloudfunctions/getSurgeData/index.js` 用 axios 抓取 shuiwei.cc（博罗水位，服务端渲染 HTML 正则提取，已验证可提取 1.03m）与 nmefc.cn（台风增水）。部署步骤：
  1. 微信开发者工具 → 云开发 → 开通并创建环境，复制环境 ID；
  2. 将 `app.js` 中 `wx.cloud.init({ env: 'dongriver-tide' })` 的 `'dongriver-tide'` 替换为你的环境 ID；
  3. 右键 `cloudfunctions/getSurgeData` → 「上传并部署：云端安装依赖」；
  4. 云开发控制台 → 数据库 → 新建集合 `boluo_history`（权限设为「所有用户可读，仅创建者可写」或「仅管理端可读写」），用于跨设备共享博罗水位历史；
  5. 编译运行「气象增减水」Tab，博罗水位应显示「今日」绿标。
- 接入**和风天气台风 API**（`/v7/tropical/cyclone`，需 Key）获取台风路径；
- 接入**水利部水文数据服务**（阿里云 API 市场有付费接口）获取博罗站水位；

## 使用方法

1. 用 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) 打开本目录。
2. 选择“测试号”或填入自己的 AppID（`project.config.json` 默认 `touristappid`）。
3. 编译预览即可在模拟器或真机查看。

## 接入真实数据（可选）

如需使用实测 / 预报潮汐数据替代本地预测，可在 `utils/tide.js` 的 `predictDay` 中替换数据来源，例如：

- [和风天气潮汐 API](https://dev.qweather.com/docs/api/ocean/tide/)：提供未来 10 天逐小时潮汐与高低潮（需 LocationID 与 API Key，并在小程序后台配置 request 合法域名）。
- 国家海洋科学数据中心潮汐预报服务接口。

注意：多数公开 API 仅提供未来数据，**历史 3 天**潮汐需专门的历史数据接口或本地缓存。
